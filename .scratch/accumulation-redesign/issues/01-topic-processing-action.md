# topic 卡复习时的处理动作

Type: prototype
Status: resolved

## Question

复习 topic 卡时，用户"不知道怎么处理"，于是只能推后（典型：`[T] 为什么不需要每日清单` 12 次复习全是 `topic a=1.5`）。要定的是：一次 topic 复习的**可完成动作**是什么、界面如何呈现。

用户已确认（Q12 / Q13）：
- 难点是**判断该提取什么**，不只是缺按键。
- 长 topic 讲了很多，不知道怎么拆成小 topic 再拆成 cloze。
- 两难：拆多了浪费，拆少了怕丢重要的东西。

待定：

1. **每次复习只要求一步**：读一遍后只做"挑出一段最值得的"，而不是一次拆完整张卡。剩余内容保留在原 topic，下次再挑。这样是否能解除"拆多/拆少"的两难？
2. **"丢了"的担心如何兜底**：原文永远保留在 topic 里（提取是复制不是剪切），丢弃只是 dismiss 标签、可撤销——是否需要在界面上明说这一点？
3. **AI 推荐**：org-sm-gptel 已能 refine/split。复习时由 AI 给出 1–2 段候选（附一句理由），用户选一段或跳过？候选用"小 topic"还是直接 cloze？
4. **完成判定**：一张 topic 什么时候算"读完了 / 退役"？
5. 动作集合：提取一段 / 丢弃 / 完成 / 推后 —— 是否足够，按键怎么映射到现有 `rsch / postpone / explain`？

原型：拿 `[T] 为什么不需要每日清单` 与另外 2 张长 topic，走一遍"一次一步"的流程，给出 AI 候选与界面文案，让用户对比感受。

## 参考

- 2026-08-04 first-principles-tutor 的 topic 设计：topic = 一段自洽陈述，优先概念（是什么）与关系（为什么），不硬拆凑数。
- 2026-08-07：挑战/AI 必须用户主动触发；第一版保留原快速路径。（这里的 AI 候选是否属于"主动触发"需确认。）

## Answer

用户确认（2026-10-16）：AI **不**在每张卡自动触发（很多卡复习很快），由用户主动按键触发。

决定：

1. **快速路径不变**：`r` 照常一秒过。
2. **新增复习菜单键（暂定 `x`，"挑一段"）**：在 topic 复习时可见，打开现有 `org-sm-card-workbench` 并直接请求 AI。
3. **新增 AI 模式"挑一段"**（加入 `org-sm-gptel--card-modes`）：只产出**一段**最值得提取的内容（小 topic，自洽陈述，优先主张 / 定义 / 因果），附一句理由；不重写正文；没有值得的就建议 dismiss 或"读完了"。一次一步，剩余内容留在原 topic。
4. **提交后回到队列**：从复习进入 workbench 时，`C-c C-c` 提交后自动对原 topic 做一次 `rsch` 并 advance；`C-c C-k` 取消则回到这张卡。
5. **"拆少了会丢"的兜底无需新机制**：提取是复制不是剪切，原文保留并继续回到队列；dismiss 可 `undismiss`。方向宁可拆少。

实现属于 org-sm 仓库（`org-sm.el` 复习菜单 + `org-sm-gptel.el` 新模式），改动小。"读完了 / 退役"的判定暂不单独建模：用现有 dismiss 表达。
